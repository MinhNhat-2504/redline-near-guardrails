- Consulted official docs: https://docs.near.org/smart-contracts/anatomy/crosscontract and https://docs.rs/near-sdk/latest/near_sdk/ . The latter resolves to **5.30.0** at lookup. Do not blindly copy its older 5.17 quickstart dependency example. Final SDK pin and toolchain must be validated by actual build.
- Official NEAR docs confirm calls/callbacks are independent; no automatic rollback across receipts. Reserve both owner funds and grant transaction slots before creating Promise. Callback success finalizes; failure releases once. Revoke cannot cancel queued transfers. No timeout release.
- MVP: native NEAR only; u128 yoctoNEAR and decimal strings in JSON. Use predecessor authority; signer identity alone cannot authorize calls through a hostile contract. Owner-signed policy parameters remain on-chain authority.
- Storage must be funded separately from transferable owner credit. Bound IDs/allowlists; charge actual storage growth. Callback state updates must not require new owner storage funding. Low callback gas/stuck pending must fail closed.
- Sandbox is local NEAR runtime evidence, distinct from SDK mock environment tests and from public Testnet proof. Never treat any one as another.
- Windows Rust absent; Ubuntu WSL available but no Rust either. Any locally prepared toolchain stays under ignored `.tooling/`, without modifying shell profiles.

## Phase 1 implementation decisions (verified locally)

- Pin `near-sdk = 5.30.0`, use its `legacy` LookupMap for immediate storage accounting; isolated crate/workspace. Toolchain observed: Rust/Cargo 1.99.1; do not use the official quickstart's older 1.86 environment as a claim of compatibility.
- SDK unit tests exercise mocked contexts/results; separate Python harness signs actual local NEAR transactions with Ed25519. Initial npm `near-sandbox@0.3.4` default binary 2.13.4/protocol 86 rejected SDK 5.30's host imports. SDK package metadata declares **minimum protocol 88**. Read-only query of public Testnet confirmed protocol 88 / nearcore 2.14.0-rc.5, so use the matching official sandbox. Final archive SHA-256 `11ff20219d0a3847ee85f14232d169072a0e105f744dc6ab9d587efbbded0a5e`; binary commit matches the Testnet status response. The earlier failure remains in evidence. No public transaction/deployment was performed.
- **Storage payer correction during review:** owner funds grant/withdraw record storage; executor separately funds intent storage, including denials. Charging denials to owner would let a compromised/revoked executor exhaust owner storage and obstruct withdrawal. Principal remains separate from all storage allowances. Storage refunds/pruning deferred.
- Direct owner transactions only (`predecessor == signer`, excluding contract itself); executor checks predecessor only. Contract-owned vaults and relayed owner operations are outside MVP scope.
- Global grant IDs immutable; use random IDs to avoid squatting. Intents are scoped by SHA-256 of a canonical JSON tuple `(grant_id, intent_id)`; withdrawals by `(owner, withdrawal_id)` with separate collection prefix. No ambiguous concatenation.
- Fixed-size callback transitions, exactly one Promise result, self-predecessor + private export, 20 Tgas callback allocation and at least 60 Tgas remaining on queueing calls. Contract account must maintain physical storage stake plus a 0.1 NEAR operator reserve. Validate budgets in sandbox before deployment.
- Initial compiler downloads were slow/stalled; archives checked against official Rust manifest. Optional direct install failed because Rust install.sh mishandles spaces in prefix; working rustc/cargo use project-local rustup sysroot. Cargo cache/target moved to an isolated Linux `/tmp/redline-near-build-*` directory for WSL I/O performance. Environment diagnostics retained locally under ignored `.tooling/diagnostics`; actual test/build/runtime evidence committed under `docs/evidence/`, normalized to UTF-8 without changing command output.
- Source inspection of `near-sdk-env 0.1.8` showed NEAR host hash/panic selection requires **`--cfg near`**. Without it, authorization failures became generic WASM traps. `.cargo/config.toml` now sets the flag only for the WASM target, and contract compilation refuses missing cfg. Native/Anchor targets unaffected. Keep named runtime-error assertions; do not weaken them to accept arbitrary traps.
- Deprecated `env::promise_result` replaced by `promise_result_checked(0, 0)`: native transfers return empty results. Only explicit Promise failure releases funds; an unexpected result payload panics and keeps reservation locked.
- `send_tx` waits until INCLUDED under a nonce ordering lock; then `tx(wait_until=FINAL)` waits outside the lock, allowing receipt overlap while verifying all refunds/callbacks. API source: https://docs.near.org/api/rpc/transactions .
- Sandbox fast-forward advances height but did not guarantee the assumed timestamp. Expiry tests now observe an actual finalized block timestamp beyond policy expiry before sending; deadline/observed timestamp recorded in JSON evidence.

## Phase 2 unsigned grant preparation

- PowerShell helper only prepares files; never invokes RPC, reads keys or signs. Unique packages preserve earlier proposals. `.tooling/near-testnet/latest-grant-path.txt` points to the newest package; older grants are not overwritten.
- Canonical `redline.near.policy.v1` is compact UTF-8 JSON with fixed field order: schema, network, contract_id, owner_id, grant_id, executor, asset, spend_cap, max_transactions, recipients, expires_at_ns, cooldown_ns. Arrays preserve reviewed order; amounts and nanosecond times are decimal strings. Hash excludes policy_hash itself; SHA-256 of those exact canonical bytes is attached to the on-chain policy. Owner signs actual contract parameters; an advisory digest never replaces those checks.
- Demo defaults: Testnet-only fixed roles, total cap 0.2 NEAR, max three transfers (settled plus pending), one named payee, cooldown zero, expiry one hour after preparation. Timestamp calculated via BigInteger from integer Unix milliseconds, without float money/time arithmetic. Duration override accepts 1–24 hours.
- Initial generated proposal fields/digest/expiry independently validated with Python. Initial receipt-verification assertion used a mistyped expected storage integer; corrected to exact Decimal('0.04833') * 10^24 and reran successfully. This was a local verification-script error, not a chain-accounting failure.
